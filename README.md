# Академія CannaMed — прототип фронтенду

Клікабельний прототип усіх екранів і станів з ТЗ v2 / списку фіч v3.
Призначення: узгодити обсяг фронтенду з клієнтом до появи Figma і підперти оцінку годин.

## Запуск

```bash
cd prototype
npm install
npm run dev     # http://localhost:5173
```

## Де що дивитися

**`/map` — карта прототипу.** Усі екрани з привʼязкою до ID фіч (F-01…F-71) і перелік станів S01–S14.

Демо-входи на `/login`: «Як лікар», «Як медпредставник», «Як адміністратор».
Статус заявки перемикається в кабінеті (вкладка «Статус доступу») — щоб показати стани
«очікує підтвердження», «підтверджено», «відхилено».

## Стек прототипу

- React 18 + Vite + React Router
- Zustand (+ `persist`) — стан фільтрів, збережених матеріалів, реєстрацій на події, прогресу тесту, згоди на cookie
- Чистий CSS з токенами брендбуку (`src/styles/global.css`): `#022622`, `#00AF5F`, `#37DB89`, `#C5F9D1`, `#FFFFFF`

> **Прод-стек — той самий: Vite + React + Zustand, без SSR.** Бекенд на Python, Node у проді
> не піднімаємо. SEO-вимоги п.10 ТЗ закриваються prerender-ом статичних маршрутів на білді
> (react-snap / vite-plugin-prerender) + мета-теги + базовий JSON-LD. Пересборка при публікації
> контенту — вебхук з CMS на білд-сервер (години на бекенді).
>
> Це свідомий компроміс: повноцінного SSR не буде, індексація динамічних сторінок залежить від
> регулярності пересборки. Зафіксувати з клієнтом письмово.

## Анімація

Уся анімація — CSS + IntersectionObserver, без анімаційних бібліотек (нуль ваги в бандлі).
Тривалості: 150 ms мікро-взаємодії, 240 ms поява блоків, 320 ms зміна сторінки.

- поява сторінки при зміні маршруту, поява карток при скролі зі стагером
- вхід/вихід модалок, cookie-банер висувається знизу, тости виїжджають збоку
- лічильники на головній рахуються вгору при потраплянні в екран
- скелетони з шимером у каталозі бібліотеки (імітація підвантаження)
- мікро-взаємодії: кнопки, чипи, картки, підкреслення в меню, shake на помилці валідації

`@media (prefers-reduced-motion: reduce)` вимикає все це для користувачів із відповідним
системним налаштуванням — обовʼязкова вимога доступності.

## Форми в модальних вікнах

Вхід, реєстрація, відновлення доступу і реєстрація на подію відкриваються в модалці поверх
поточної сторінки — користувач не втрачає контекст.

Маршрути `/login`, `/register`, `/recover` лишаються робочими: вони потрібні для прямих посилань
з листів, закладок і для випадку, коли JS не відпрацював. Форми винесені в окремі компоненти
(`RegisterForm`, `LoginForm`, `RecoverForm`, `EventRegisterForm`) і використовуються і там, і там —
дубльованої верстки немає.

`src/components/Modal.jsx` — спільна модалка: анімація входу і виходу, Esc, блокування скролу,
базовий фокус-трап, на мобільному відкривається як нижній лист.

## 3D-модель молекул (опція, не входить в Етап 1)

Сторінки матеріалів з темами «фармакологія» і «ЕКС» містять інтерактивний вʼюер ТГК/КБД:
обертання, підсвітка функціональних груп, перемикання між молекулами.
Дивитись: [/library/m4](http://localhost:5173/library/m4) або `/library/m2`.

**Ключовий дидактичний момент:** ТГК і КБД мають однаковий склад C₂₁H₃₀O₂, але в ТГК піранове
кільце замкнене (жорстка трициклічна система, звідси зв’язування з CB1 і психоактивність),
а в КБД розімкнене (гнучка молекула, низька спорідненість до CB1). На 2D-схемі це пояснювати
важко, на 3D-моделі видно одразу.

**Вага контрольована:** Three.js вантажиться динамічним імпортом і тільки після кліку
користувача. Головний бандл — 92 КБ gzip, вʼюер — окремий чанк 125 КБ gzip, який більшість
відвідувачів ніколи не завантажить.

**Про достовірність:** у прототипі геометрія схематична — склад і звʼязність відповідають
структурі, але координати ідеалізовані і стереохімія не відтворена. Це явно написано під
моделлю. Для продакшену треба вантажити SDF з 3D-координатами з PubChem
(Δ9-THC — CID 16078, CBD — CID 644019) і віддати на вичитку медичному рецензенту.
Парсер SDF V2000 уже написаний: `parseSDF()` у `src/mock/molecules.js`.

## Структура

```
src/
  components/   Layout (хедер, футер, cookie-банер, модалки, тости) + UI-примітиви
  pages/        Публічні сторінки, auth/, cabinet/, Admin, Map
  store/        authStore, uiStore, contentStore (бібліотека, події, пошук, курс)
  mock/data.js  Усі мокові дані — у проді замінюються на API CMS/LMS
  styles/       Дизайн-система в токенах
```

## Що свідомо НЕ реалізовано

- Реальний бекенд, авторизація, завантаження файлів (усе на моках у localStorage)
- Навчальна частина (плеєр, тести, сертифікати) показана як UI-демо — у базовому сценарії
  оцінки вона живе всередині LMS (Softbook / SendPulse), а не на нашому фронті
- SEO-метадані, schema.org, sitemap — потребують SSR, тому в прототипі відсутні
